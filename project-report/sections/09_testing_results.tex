\subsection*{9.1 Introduction}
Testing is a critical phase in the development of the CypherRoll system to ensure that all gaming, cryptographic, and financial settlement components function correctly, securely, and efficiently. The objective of testing is to validate the system against its functional requirements, identify potential vulnerabilities, and ensure stable performance under concurrent load.

\subsection*{9.2 Testing Environment}
The CypherRoll platform was evaluated across both controlled local sandboxes and public testnets:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Blockchain Testnets:} The escrow vault was deployed and tested on the \textbf{Ethereum Sepolia} and \textbf{Base Sepolia} test networks using MetaMask, enabling zero-cost financial transaction testing with free faucet ETH.
    \item \textbf{Local Application Server:} Next.js 14 development and production build servers running on Node.js v20.
    \item \textbf{Statistical Test Harness:} Automated verification scripts (\texttt{tests/test\_provably\_fair.js}) utilizing Node.js Crypto to simulate thousands of consecutive gaming rounds.
\end{itemize}

\subsection*{9.3 Functional Testing}
Functional testing was conducted across all core user journeys:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{MetaMask Wallet Authentication:} Validated that connecting MetaMask initiates the SIWE personal sign flow, verifies nonces, and successfully provisions player sessions.
    \item \textbf{Deposit Receipt Verification:} Confirmed that submitting a valid on-chain transaction hash from Base Sepolia or Ethereum Sepolia correctly queries the RPC node, verifies confirmation status, and credits the user's ledger balance.
    \item \textbf{Gameplay \& Payout Logic:} Tested that placing bets in CypherDice and CypherCrash deducts the wager atomically and credits payouts calculated by the provably fair formula upon winning.
    \item \textbf{EIP-712 Withdrawal Voucher Generation:} Verified that requesting a withdrawal generates a valid typed structured signature from the operator account that can be verified and claimed on-chain.
\end{itemize}

\subsection*{9.4 Security Testing}
Security testing focused on neutralizing critical vulnerabilities:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Reentrancy Defense:} Audited \texttt{CypherRollVault.sol} to ensure reserves and nonces update before external transfers, neutralizing reentrancy exploits.
    \item \textbf{Replay Nonce Verification:} Verified that attempting to reuse an existing withdrawal voucher or submitting an out-of-order nonce fails with \texttt{"Invalid nonce sequence"}.
    \item \textbf{Double-Crediting Guard:} Tested that submitting an already-processed deposit transaction hash returns an immediate idempotency rejection.
    \item \textbf{AML Sanctions Screening:} Verified that simulated sanctioned addresses are identified by the security oracle and automatically placed into quarantine.
\end{itemize}

\subsection*{9.7 Limitations Identified}
Despite successful testing, several real-world limitations were noted:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Public RPC Throttling:} Free public JSON-RPC nodes on Ethereum Sepolia periodically experience rate limiting under rapid batch querying, indicating that production deployments require dedicated RPC providers (e.g., Alchemy or Infura).
    \item \textbf{Operator Liveness Dependency:} Generating instant EIP-712 withdrawal vouchers requires active operator server quorum. If the backend is offline, withdrawals pause until connectivity is restored.
\end{itemize}
